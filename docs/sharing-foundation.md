# Sharing foundation

Free Dealer and Business accounts use the normal permanent user identity. Free signup does not create a billing invoice. Desktop access remains restricted. Admin → Businesses → Sharing usage & access can activate Dealer Desktop after the subscription is arranged; this retains the user ID, contributions and Business workspace membership. It does not collect payment or create a new subscription automatically.

## Live sharing

- New links read the owner's current asset records on each request. Open enquiry pages refresh every 30 seconds while visible and when focused.
- New umbrella links follow the saved umbrella ID, including future members and excluding removed members. Owners see this disclosure before sharing.
- Stable asset IDs identify contributions, so changing umbrella membership cannot redirect a correction to a different asset.
- The chosen photo/valuation boundaries and existing contribution permissions still apply. Revocation, suspension and current ownership are checked on the server.
- History and Revoke access are available in Choose to share. Revoking one token leaves separately created links intact. Revoked links cannot be reopened; an already downloaded file cannot be recalled.
- Previously created asset links with asset IDs read live records. Older umbrella links without a group ID retain their original selection; create a new umbrella link to follow changing membership.
- Older directory-email requests that contain only a snapshot cannot safely resolve live asset IDs. They ask for a new share rather than display stale data. New directory emails use the live sharing flow.
- Attached PDF/Excel reports remain the files deliberately attached at sending time. They are not regenerated by refreshing the asset page.

## Usage and sessions

All draft allowances are observation-only. Zero does not block access. No reset period or paid credit debit is implemented in this foundation.

| Metric | Meaning |
| --- | --- |
| Assets received | Distinct asset IDs made available to a verified account through a targeted share, inbox reconciliation or authorised open. Repeated shares/opens of the same asset do not increase this total. This is not email delivery confirmation. |
| Enquiries opened | One authorised open per link and signed-in session. Landing-page views and owner previews do not count. |
| Uploads | Successfully committed external enquiry submissions, with stored bytes. |
| Contributions | External serial/replacement-price correction records, deduplicated by correction ID and field. |
| Email attempts | Provider calls for directory asset emails, with separate accepted/failed outcomes. Acceptance does not prove inbox delivery. |

Usage belongs to the permanent account, not browser storage, and survives sign-out and upgrade. It is not retroactively reconstructed for old shares and contributions. Draft limits and manual activations have an admin audit trail.

Free accounts have a 12-hour maximum session and expire after 30 minutes without an authenticated request. Refreshes count as requests. Closing a browser window cannot reliably signal logout; use Sign out for immediate logout. Normal password-manager autofill remains available.

The ledger is ready for maintenance reminder email metering, but this change does not add a scheduled reminder sender. Multi-email organisation management, recurring billing automation and enforcement of decided allowances remain follow-up work.

## Validation / rollout

Migration `123-live-sharing-foundation.sql` is additive and repeatable. The existing lazy schema setup also creates the new tables/columns. No production migration or deployment is performed by opening the PR.

Test a free signup, verify its email, open an owner-sent link, edit the owner's usage/serial, and reopen the same link. Add/remove an umbrella member and repeat. Use History → Revoke access and confirm the recipient loses access. Check usage in Admin → Businesses → Sharing usage & access; setting draft allowances to zero must not block these operations.
